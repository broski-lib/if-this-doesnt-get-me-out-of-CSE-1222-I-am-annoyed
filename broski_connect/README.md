# broski_connect

A gRPC-based remote admin tool. A central **server** brokers commands between an
admin **client** and managed device **agents**. The wire format and service
contracts live in `proto/service.proto` and are compiled to C++ at build time.

> Status: early prototype. The service surface in `service.proto` is the
> source of truth; some of the `.cpp` files in `src/` are still being ported to
> it and do not compile against the current proto yet.

## Layout

```
broski_connect/
├── CMakeLists.txt        # builds bc_server and bc_client from src/*.cpp
├── proto/
│   └── service.proto     # AdminService + AgentService contracts
└── src/
    ├── server.cpp        # gRPC server, implements both services
    ├── client.cpp        # admin-side gRPC client (stub, in progress)
    └── agent.cpp         # device-side gRPC client (stub, in progress)
```

## Prerequisites

You need a C++17 compiler, CMake 3.15+, and the gRPC + Protobuf C++ runtimes
plus the `protoc` and `grpc_cpp_plugin` code generators.

Arch:
```bash
sudo pacman -S base-devel cmake grpc protobuf
```

Debian / Ubuntu (22.04+):
```bash
sudo apt install build-essential cmake pkg-config \
                 libgrpc++-dev libprotobuf-dev protobuf-compiler \
                 protobuf-compiler-grpc
```

macOS (Homebrew):
```bash
brew install cmake grpc protobuf
```

Verify the toolchain is discoverable by CMake:
```bash
protoc --version
grpc_cpp_plugin --version
```

## Build

The first build runs `protoc` against `proto/service.proto` and generates the
gRPC stubs under `build/generated/`. A static library `proto_gen_lib` is built
from those stubs and linked into the executables.

```bash
cd broski_connect
cmake -S . -B build
cmake --build build -j"$(nproc)"
```

Artifacts land in `build/`:
- `build/bc_server` — gRPC server
- `build/bc_client` — admin client (see status note above)

Clean rebuild:
```bash
rm -rf build
cmake -S . -B build
```

## Run

The server listens on `[::]:5000` (plaintext). The clients in `src/` default
to `0.0.0.0:5000`.

Start the server (terminal 1):
```bash
./build/bc_server
# -> Server listening on [::]:5000
```

In a second terminal, point a client at it:
```bash
./build/bc_client
```

The `bc_client` / `bc_agent` binaries are minimal smoke tests — they open a
channel to `localhost:5000` and fire a single RPC. They will report a
`UNIMPLEMENTED` status from the server until the matching handler in
`server.cpp` is filled in (every method is currently a `// TODO!` stub that
returns `OK` with an empty response).

## Editing the proto

`proto/service.proto` is the contract. After changing it, wipe `build/` (or at
least `build/generated/`) so the next configure re-runs `protoc`:

```bash
rm -rf build/generated
cmake --build build
```

## Editor / language server

`compile_commands.json` is generated by CMake into the build directory. To
make clangd (or similar) see the generated proto headers, symlink it next to
`CMakeLists.txt`:

```bash
ln -sf build/compile_commands.json compile_commands.json
```
